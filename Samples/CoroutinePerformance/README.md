# 协程性能样例

这个独立控制台样例测量 Core 协程调度开销，不包含 Godot、渲染、资源加载或游戏业务。它不打包为 NuGet，也不替代原生引擎验收。

## 运行

需要 .NET 10 SDK。从仓库根目录执行：

```bash
dotnet run --project Samples/CoroutinePerformance/CoroutinePerformance.csproj -c Release
```

标准输出为 JSON，包含运行时、操作系统、逻辑处理器数及每次测量。可以将它重定向到忽略的 `.local/` 目录保存本机证据。不要在其他构建、测试或游戏进程占用 CPU 时比较结果。

## 工作负载

- 100、1000、10000 活跃协程分别覆盖持续等待和五档优先级的逐次恢复。
- 每项预热 2000 次，再测量 10000 次阶段推进，完整矩阵重复三次。
- 累计启动 100000 个短生命周期父子协程，并在并发父流程不超过 1000 的情况下排空；随后测量空闲开销与槽位存储边界。
- 逐次推进使用共享的无状态等待指令，排除业务侧创建等待对象的分配。真实游戏仍需单独测量自己的业务代码。

## 结果边界

样例检查稳定推进期间调度器线程零分配，并以 1000 活跃协程 P95 不超过 1 ms、P99 不超过 2 ms 为本机预算。10000 活跃协程用于观察压力边界，不设置同样的时间门槛。超出预算、存在分配或创建销毁未排空时退出码非零。

时间预算是这个工作负载的工程目标，不是所有设备的性能承诺。P95/P99 是单次调度推进的样本分位数，不是渲染帧率；需要在目标设备、实际引擎和业务负载下重新测量。

Core 接入方式见[协程系统](../../docs/zh-CN/core/coroutine.md)，Godot 宿主接入见[Godot 协程](../../docs/zh-CN/godot/coroutine.md)。
