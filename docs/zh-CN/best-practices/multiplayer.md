# 多人游戏接入边界

GFramework 的 DI、事件、状态及生命周期可用于组织进程内应用。框架没有因此自动提供网络传输、服务端权威、预测回滚、复制协议或断线重连；这些能力需要所选网络库与应用自己的协议实现。

## 保持业务与传输分离

将可测试的规则和用例放进普通 C# 项目。网络适配器负责接收与验证消息，再调用明确的应用服务；业务对象不读取套接字、容器或引擎节点。

一个消息应声明身份、版本和必要的序号或关联信息。服务器重新校验操作权限和业务约束，不以客户端提交的最终状态作为权威事实。重复、乱序与超时如何处理由具体协议决定。

## 本地事件不是网络协议

IEventBus 的 Publish 是进程内同步调用，在发布线程执行订阅者。它没有网络顺序、可靠投递、重放、确认或持久化保证。只把明确选择的业务消息映射为网络消息，不序列化任意 CLR 事件类型发送到远端。

需要输入预测、状态快照或服务器复制时，应分别定义本地状态、权威状态与同步策略，避免让 UI Store、网络缓存和领域对象同时任意修改同一权威值。

## 连接与会话生命周期

为连接、房间或会话建立明确的资源所有者。停止接收新消息后，取消并等待处理中的任务，再释放会话依赖与订阅。后台接收线程通过宿主调度器把需要修改节点的动作交回主线程。

## 验证

先验证离线业务用例，再对所选网络适配器测试重复包、乱序、断线、超时、权限失败和重连。原生宿主、真实网络与负载能力需要独立验收；本地事件测试或单机示例通过不能代替这些结论。
