# 移动平台验证与优化

移动平台的性能与生命周期取决于设备、系统、引擎与内容。先选择实际支持范围，再设定该范围的帧时间、内存、启动和耗电预算；框架不提供统一的包体、内存或续航达标保证。

## 生命周期与持久化

由宿主适配器处理切入后台、恢复和退出等平台通知，将明确的应用操作交给构造注入的服务。暂停游戏模拟不等于所有后台任务已经停止，也不等于存档已完成。

重要状态采用可恢复的持久化策略，测试写入失败、磁盘空间不足、中断后重启和备份恢复。不能假定系统终止进程前一定给予完整异步清理时间。

## 资源与内存

场景拥有其资源租约和事件订阅。退出时停止新请求、结束使用者并归还租约；使用 UnloadAll 只清理没有租约的缓存，避免强制释放仍在使用的资源。原生纹理、场景节点和托管堆分别观察，托管 GC 数值不能代表总内存。

长会话测试加载/卸载循环、菜单往返、内容切换和反复暂停恢复，确认引用数量与内存能够稳定。不要把频繁强制 GC 作为资源所有权问题的修复。

## 帧循环、输入和界面

按实际瓶颈调整更新频率、资源大小、绘制和分配。UI 状态变化时更新视图，避免无变化的逐帧重建。触摸、手柄、键盘与不同显示尺寸分别验收，保留必要的返回、暂停和确认行为。

需要访问活动 Godot 场景树的动作通过宿主调度器回到主线程。后台加载和状态缓存不意味着所有引擎 API 都可在后台调用。

## 设备验收

覆盖冷启动、持续玩法、反复场景切换、后台恢复、旋转或窗口尺寸变化、低存储与异常退出后恢复。记录构建、设备、内容规模和限制，再描述支持范围。桌面测试与纯托管测试不能代替移动设备验收。
