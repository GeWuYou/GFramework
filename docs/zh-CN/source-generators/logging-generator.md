# 日志生成器

## 概述

日志生成器是 `GFramework.Core.SourceGenerators` 中的一个 Source Generator。它为标注了 `[Log]` 特性的类型生成一个实例日志属性，属性经当前实例绑定的架构上下文解析 `ILoggerFactory` 并创建标准 `Microsoft.Extensions.Logging.ILogger`，结果会被缓存复用。

生成的属性不是全局静态入口：日志工厂来自当前实例绑定的架构上下文，不同架构实例的日志互不影响。面向 DI 容器的普通服务应直接构造注入 `ILogger<T>`，不要使用本特性。

## 基本用法

### 标注类型

```csharp
using GFramework.Core.SourceGenerators.Abstractions.Logging;

[Log]
public partial class MySystem : ContextAwareBase
{
    public void DoSomething()
    {
        // 生成的日志属性可直接使用，默认属性名为 _log
        _log.LogInformation("执行操作");
    }
}
```

### 生成代码

上面的代码在编译时会生成类似下面的分部定义：

```csharp
// <auto-generated />
using Microsoft.Extensions.Logging;

public partial class MySystem
{
    /// <summary>生成的日志属性底层缓存；首次访问时按当前上下文解析并复用。</summary>
    private ILogger? __gFrameworkLogBacking;

    /// <summary>
    /// 自动生成的日志记录器。
    /// </summary>
    /// <remarks>日志工厂经由当前实例绑定的架构上下文解析；访问未绑定上下文的实例会抛出异常。</remarks>
    private ILogger _log => __gFrameworkLogBacking ??=
        Context.GetService<ILoggerFactory>().CreateLogger("MySystem");
}
```

生成器只生成日志属性，不生成日志方法。`LogInformation`、`LogDebug`、`LogError` 等方法来自标准 `ILogger` 接口。

## 上下文要求

生成的属性通过当前实例绑定的架构上下文解析 `ILoggerFactory`，因此标注类型必须能访问架构上下文，满足以下任一条件：

- 实现 `IContextAware`（包括由 `[ContextAware]` 生成的实现）
- 派生自 `ContextAwareBase`
- 同一编译中标注了 `[ContextAware]`

否则生成器报错误诊断 `GF_Logger_001`，例如：

```text
error GF_Logger_001: 'MyService' uses [Log] but has no architecture context:
implement IContextAware, derive from ContextAwareBase, or mark the type
[ContextAware]; DI-activated services should inject ILogger<T> instead
```

解析不到上下文的实例（例如尚未绑定架构）在首次访问属性时会抛出异常。

## 配置选项

### 自定义属性名称

```csharp
[Log(FieldName = "_logger")]
public partial class MyClass
{
    public void DoSomething()
    {
        _logger.LogInformation("使用自定义日志属性名");
    }
}
```

### 自定义日志类别

```csharp
[Log("Gameplay")]
public partial class GameplaySystem
{
    public void Update()
    {
        // 日志类别为 Gameplay
        _log.LogInformation("游戏逻辑更新");
    }
}
```

### 访问修饰符

```csharp
[Log(AccessModifier = "protected")]
public partial class ProtectedLogger
{
    // 生成 protected 日志属性
}
```

### 配置选项说明

| 参数 | 类型 | 默认值 | 说明 |
|----------------|---------|-----------|---------------------------------|
| Name | string? | null | 日志类别名（默认使用类名） |
| FieldName | string | `_log` | 生成的属性名称 |
| AccessModifier | string | "private" | 访问修饰符（private/protected/public） |

`IsStatic` 选项已移除：生成的属性始终是实例属性，日志工厂经由实例上下文解析。

## 与其他模块集成

### 与 Godot 节点集成

```csharp
using GFramework.Core.SourceGenerators.Abstractions.Logging;
using Godot;

[Log]
[ContextAware]
public partial class GodotController : Node
{
    public override void _Ready()
    {
        _log.LogInformation("控制器已准备就绪");
    }
}
```

### 与架构组件集成

```csharp
[Log]
public partial class PlayerSystem : AbstractSystem
{
    protected override void OnInit()
    {
        _log.LogInformation("系统初始化");
    }
}
```

## 什么时候用 [Log]，什么时候构造注入

- 用 `[Log]`：
  - Godot 节点、controller、system 等架构组件上有大量重复 logger 样板
  - 你已经引用 `GFramework.Core.SourceGenerators`
  - 类型本来就绑定在某个架构实例上
- 构造注入 `ILogger<T>`：
  - 类型由 DI 容器激活，不依赖架构上下文
  - 你希望 logger 的来源由容器注册的 `ILoggerFactory` 决定

两者面向同一个标准 `ILogger` 契约，可组合使用：架构组件用 `[Log]`，容器服务用构造注入。

## 常见问题

### Q: 为什么需要 partial 关键字？

**A**: 源生成器需要向现有类型追加成员，`partial` 允许一个类型的定义分布在多个文件中。

### Q: 可以在静态类型中使用吗？

**A**: 不可以。生成的属性是实例属性，需要通过实例绑定的上下文解析日志工厂；静态类型没有实例上下文。无架构的静态入口或普通服务请注入 `ILogger<T>` 或使用 `ILoggerFactory.CreateLogger(...)`。

### Q: 如何自定义日志工厂？

**A**: 通过 `ArchitectureConfiguration.LoggerProperties.LoggerFactory` 提供标准 `ILoggerFactory`，见 [架构与日志](../core/logging.md#架构实例接线)。生成代码经架构上下文解析的就是这个工厂。
