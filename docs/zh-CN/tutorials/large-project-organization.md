# 项目组织与依赖边界

以功能作为查找代码的入口，功能内部按领域规则、应用用例和宿主适配组织。先建立必要边界，再根据实际依赖成本拆程序集。

推荐起点为纯 C# Core 与宿主项目：Core 包含规则、用例和需要的端口；宿主包含引擎节点、存储、配置、内容与 UI 适配，在组合根连接它们。领域规则不引用引擎或容器。

一个功能应能从用户操作追到应用方法、领域行为和基础设施调用。简单调用直接表达；只有独立观察者需要通知时使用事件。接口用于隔离真实变化点，避免为每个类增加无实际用途的接口和转发层。

变更通过测试保护：规则用例可不启动引擎运行，宿主操作通过原生测试验收，依赖边界通过程序集引用检查。例行新增功能应在所属模块完成，不要求修改全局服务定位器。

完整实现与创建步骤见 [进阶游戏教程](./godot-advanced-project.md)，简单接入见 [完整 Godot 项目](./godot-complete-project.md)。
