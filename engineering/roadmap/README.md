# 实施路线图

路线图记录重要目标、依赖、验收条件和唯一的当前状态，不替代源码契约、架构决策或任务管理工具。

- [保留的后续事项](retained-followups.md)：仍需按实际需求取舍的其他候选工作。

## 状态与维护

状态使用 planned、in_progress、blocked、done、deferred。done 表示范围内验收已完成；blocked 写明具体条件；deferred 说明重新启动条件。状态变化须有当前证据，不能继承历史勾选或 CI 结果。

复用已有条目，只在目标、依赖、验收或状态发生实质变化时更新。保留有后续价值的验收结论与限制，不为任务、会话或执行轮次新增恢复文件，不记录命令流水、逐次测试数字、分支/PR 交接和 agent 工作过程。实际源码与必要文档的变更由 Git 保存。

当前顺序：文档职责治理 → 统一 DI/资源/实例隔离 → 独立采用边界与调用收敛 → 游戏服务独立采用、强类型 UI 与 Godot 游戏闭环。其他增强由实际使用需求触发。

## 按需 CI

状态：done。日期：2026-11-07。目标是按模块实际依赖选择 PR 验证，并隔离框架与配置工具的发布标签；规则与入口见[开发与验证](../development/workflow.md#按需-ci)。

验收：独立改动跳过无关任务，跨模块引用、共享输入与累计改动仍覆盖实际使用方；无法可靠判断时全量验证；所选任务失败或意外跳过不能通过汇总；配置工具标签不触发框架发布。GitHub 自动依赖提交保留独立管理。

验收结论：独立改动与累计改动均按实际影响范围选择验证；无关任务可跳过，所选任务失败或缺失时汇总不能通过。框架与配置工具的发布标签保持隔离。

限制：按需 CI 只作用于 GitHub Actions 的 PR 验证；远端 CodeQL 定时扫描与自动依赖提交按各自计划独立运行，不在本条目验收内。
